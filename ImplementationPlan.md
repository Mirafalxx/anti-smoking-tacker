# План реализации трекера курения

## 1. Результат и принятые решения

Мобильное веб-приложение на русском языке: крупный календарь, кнопка «+1 сигарета», просмотр записей за день и статистика за выбранный период. Авторизация через Google, персональные данные в Firebase, публикация на GitHub Pages.

Основной сценарий: сразу после курения нажать кнопку — приложение автоматически запишет дату и время. Дни без курения пользователь подтверждает отдельно; незаполненный день означает «Нет данных».

Стек: React, TypeScript, Vite, CSS Modules, Firebase Authentication и Cloud Firestore. Отдельный сервер и Cloud Functions не нужны.

## 2. Интерфейс

- Светлая тема: молочный фон, графитовый текст, приглушённый зелёный акцент. Без ярких заливок и оценочных сообщений.
- Нижняя навигация на телефоне: «Календарь» и «Статистика». Профиль и выход доступны в шапке.
- Календарь на всю доступную ширину: семь колонок, неделя с понедельника, переключение месяцев и кнопка «Сегодня».
- В каждой ячейке: дата и количество сигарет, подтверждённый ноль либо отсутствие данных. Сегодня и выбранная дата выделены отдельно.
- Постоянно доступная кнопка «+1 сигарета» добавляет запись за текущий момент независимо от открытого месяца.
- Нажатие на дату открывает нижнюю панель: итог, список времени курения, исправление даты/времени, удаление ошибочной записи и отметка «Не курил». Для прошедшего дня можно добавить отдельную запись вручную; будущие записи запрещены.
- Статистика: текущий месяц по умолчанию, последние 7/30 дней и произвольный диапазон включительно. Показывать общий итог, столбчатый график и список вида «11.11.2026 — 5 сигарет». Незаполненные дни обозначать явно.

## 3. Данные, авторизация и офлайн

- Профиль `users/{uid}` хранит часовой пояс, определённый при первом входе. Использовать его на всех устройствах; сохранять принадлежность записи к дню при последующих поездках.
- Каждая сигарета — отдельный документ `users/{uid}/events/{eventId}`: время события, ключ дня `YYYY-MM-DD`, время создания. Дневные итоги вычислять из записей, чтобы параллельные добавления не перезаписывали общий счётчик.
- Подтверждение «Не курил» хранить отдельно по дате. Оно доступно при отсутствии сигарет; при появлении записи показывать фактическое количество.
- Запрашивать записи только за отображаемый месяц или выбранный период, обновлять интерфейс через подписки Firestore.
- Правила Firestore разрешают доступ только владельцу `uid`, проверяют поля и типы документов; остальные обращения запрещены.
- Google-вход запускать через `signInWithPopup` непосредственно по нажатию. Обрабатывать отмену, блокировку окна и отсутствие сети; проверить работу на Android Chrome и iOS Safari. Основание: [рекомендации Firebase для авторизации](https://firebase.google.com/docs/auth/web/redirect-best-practices).
- Включить постоянный кеш Firestore с поддержкой нескольких вкладок. Различать «Сохранено на устройстве», «Ожидает синхронизации» и ошибку записи. При неполном офлайн-кеше не выдавать статистику за полную. [Механизм офлайн-доступа Firestore](https://firebase.google.com/docs/firestore/manage-data/enable-offline).
- Добавить PWA: manifest и service worker для оболочки приложения. После первого успешного открытия приложение должно запускаться без сети; первый вход требует интернета.
- При выходе остановить подписки и очистить пользовательское состояние и постоянный кеш. Если есть неотправленные изменения, сохранить текущую сессию до синхронизации и объяснить причину.

## 5. Проверка готовности и границы первой версии

- Пять добавлений дают ровно пять сигарет в календаре и статистике; исправление и удаление корректно пересчитывают оба экрана.
- Проверены границы месяцев, високосный февраль, полночь и включение обеих дат выбранного периода.
- Ноль отличается от отсутствия данных; будущие даты недоступны для ввода.
- Офлайн-добавления переживают перезапуск и синхронизируются без дублей; независимые добавления с двух устройств сохраняются.
- Второй аккаунт не видит данные первого ни в интерфейсе, ни через прямые обращения к Firestore.
- Автотесты покрывают расчёты, даты, основные действия и правила доступа. Финальная проверка включает реальный Google-вход и офлайн-запуск на телефоне.
- Опубликованная версия загружает ресурсы, открывает внутренние экраны и обновляется без 404.

Первая версия включает только учёт курения и статистику. Напоминания, денежная экономия, медицинские показатели и цели отказа в неё не входят. Firebase и GitHub настраиваются в аккаунтах владельца; административные ключи в браузерную сборку не добавляются.

### Технические замечания

- Для дальнейшей разработки и CI выбран Node.js 24.12+. Текущая среда Node.js 20 успешно выполнила сборку и unit-тесты, но выдаёт предупреждения требований Firebase SDK.
- После обновления зависимостей и overrides аудит не сообщает критических, высоких или умеренных уязвимостей. Остаются четыре предупреждения низкой серьёзности в транзитивных инструментах сборки PWA.
- Реальный Google-вход на Android/iOS, облачные правила в эмуляторе, синхронизация устройств и опубликованный GitHub Pages ещё не проверены. Деморежим не заменяет эти проверки.
